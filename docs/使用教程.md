# Docker 一键启动与使用教程

这份说明面向本机第一次把 Auto Ontology 跑起来的人。全程只需要 Docker Desktop（含 Compose v2）。浏览器请打开 `http://localhost:3000`。

## 1. 启动后有什么

一条命令会拉起整套 Compose。里面只有一个数据库容器：

| 容器 | 作用 | 本机地址 |
| --- | --- | --- |
| `postgres` | PostgreSQL 17 + pgvector，镜像 `pgvector/pgvector:pg17` | `localhost:5432` |
| `auto-ontology-frontend` | 网页 | `http://localhost:3000` |
| `auto-ontology` | API | `http://localhost:3001` |
| `auto-ontology-ingestion-service` | 入库服务 | `http://localhost:3002` |
| `pgadmin` | 数据库管理界面 | `http://localhost:5050` |

应用库名是 `auto_ontology`（`.env` 里的 `POSTGRES_DATABASE`）。Alembic 维护 `public`，Prisma 维护 `frontend`。向量扩展 `vector` 在第一次写入嵌入时建到 `vdb`。

Wide World Importers 不是这个栈自带的库。它是可选的示例业务库，需要另跑种子脚本才会出现。

## 2. 启动

在仓库根目录执行：

```bash
bash dev_tools/compose_up.sh
```

第一次运行时，如果还没有 `.env`，脚本会从 `.env.example` 复制一份，并做两件事：

- 注释掉示例里的 `CONNECTION_STRINGS`。那一行指向不存在的用户和库，留着会让 API 在启动时连不上数据源。
- 把示例里过短的 `AUTH_SECRET` 换成一串随机值。

已经存在的 `.env` 不会被覆盖。脚本接着执行 `docker compose up -d --build`，并等到登录页可以打开。第一次要构建镜像，需要几分钟。

看到下面两行就可以打开浏览器：

```text
UI:       http://localhost:3000
API:      http://localhost:3001
```

请用 `localhost`，不要用 `127.0.0.1`。

## 3. 登录

打开 http://localhost:3000 。页面标题是 Auto Ontology，中间是 Email 和 Password。

默认管理员来自 `.env`：

| 项 | 变量 | `.env.example` 里的值 |
| --- | --- | --- |
| 邮箱 | `AUTO_ONTOLOGY_ADMIN_EMAIL` | `admin@nvidia.com` |
| 密码 | `AUTO_ONTOLOGY_ADMIN_PASSWORD` | `autoontologypassword123` |

系统关闭了自助注册，只能用这里创建的管理员，或之后在 Settings → Users 里邀请的账号。对外暴露这台机器之前，改掉 `.env` 里的管理员密码、`POSTGRES_PASSWORD` 和 `PGADMIN_PASSWORD`。

登录成功后进入 http://localhost:3000/chat 。

## 4. 界面

左侧是一条图标栏，鼠标移上去会展开名称。管理员能看到全部入口：

| 入口 | 地址 | 用来做什么 |
| --- | --- | --- |
| Chat | `/chat` | 用自然语言提问。语义层还没建好时，页面中央是 “Semantic Layer Not Ready”。 |
| Discovery | `/discovery` | 按业务对象搜索目录。 |
| Terms | `/terms` | 查看和整理术语。 |
| Analysis | `/analysis` | 查看分析定义。 |
| Exploration | `/exploration` | 查看对象之间的关系。 |
| Data | `/data` | 浏览已入库的库、schema、表和列。 |
| Analytics | `/analytics` | 查看使用情况。仅管理员。 |
| Settings | `/settings` | 连接、用户、规则和模型相关设置。仅管理员。 |

Settings 会打开左侧第二节菜单。当前没有设置 `CONNECTION_STRINGS` 时，第一项是 Connections。其余依次是 Zones、Tags、Rules、PII Settings、Semantic Input、Users、Single Sign-On、Semantic Compilation、Agent Settings、Import / Export。

## 5. 为什么还不能提问

刚启动时 Chat 会显示：

> Semantic Layer Not Ready
>
> The semantic layer hasn't been created yet, so I can't answer questions.

这是预期状态。提问需要两样东西，现在都还没有：

1. **模型密钥。** 在 `.env` 里把 `DEFAULT_MODELS_API_KEY` 从 `nvapi-your-api-key-here` 换成 [build.nvidia.com](https://build.nvidia.com) 的 `nvapi-...` 密钥。改完后执行 `docker compose up -d` 让 API 读到新值。
2. **一个真实数据源。** 打开 Settings → Connections，页面在没有连接时显示 “No Connections Created Yet”。在这里添加 PostgreSQL、MySQL、Databricks、Snowflake 等连接。也可以把 `CONNECTION_STRINGS` 设成真实的连接串；不要保留示例里的 `user:password@localhost:5432/wideworldimporters`。

数据源入库并完成语义层编译之后，Chat 才能回答问题。可选的 Wide World Importers 示例数据的导入步骤写在仓库根目录 `README.md` 的 Quickstart 里。

## 6. 看数据库

pgAdmin 在 http://localhost:5050 。邮箱和密码是 `.env` 里的 `PGADMIN_EMAIL`、`PGADMIN_PASSWORD`。示例邮箱同样是 `admin@nvidia.com`。

在 pgAdmin 里登记服务器时，主机填 `postgres`（容器网络内）或本机的 `host.docker.internal`，端口 `5432`，数据库 `auto_ontology`，用户是 `POSTGRES_USER`（示例为 `postgres`）。

也可以在本机用客户端连 `localhost:5432`，密码是 `POSTGRES_PASSWORD`。

## 7. 停止和再次启动

在仓库根目录：

```bash
docker compose stop
docker compose start
```

`stop` 保留数据和镜像。下次想连构建一起启动，仍然使用：

```bash
bash dev_tools/compose_up.sh
```

不要执行 `docker compose down -v`，除非你确定要删掉 Postgres 数据卷。那个卷里有应用库 `auto_ontology`。
